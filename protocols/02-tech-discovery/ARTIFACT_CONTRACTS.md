# Artifact Contracts

## 01_PRODUCT_TO_TECH_MAP.md
Debe mapear cada capacidad del producto a requerimientos técnicos neutrales.

## 02_DOMAIN_AND_DATA_MODEL.md
Debe contener entidades, relaciones, lifecycle, invariantes, sensibilidad de datos e hipótesis.

## 03_ARCHITECTURE_DRIVERS.md
Debe priorizar drivers con impacto y evidencia.

## 04_TECHNICAL_OPTIONS.md
Debe comparar alternativas por categoría sin forzar componentes innecesarios.

## 05_SECURITY_PRIVACY_COMPLIANCE.md
Debe contener threat-oriented discovery, no checklist superficial.

## 06_INTEGRATIONS.md
Debe registrar criticidad, contratos, fallbacks y riesgos externos.

## 07_DELIVERY_AND_OPERATIONS.md
Debe cubrir el ciclo completo de entrega y operación.

## 08_ARCHITECTURE_HYPOTHESES.md
Debe proponer varias opciones plausibles y sus triggers de evolución.

## 09_TECHNICAL_SYNTHESIS_V1.md
Debe ser una síntesis coherente previa al red-team.

## TECH_DECISION_LEDGER_V1.md / FINAL
Cada registro debe incluir:
- Decision ID
- Context
- Decision
- Alternatives
- Evidence
- Rationale
- Confidence
- Reversibility
- Cost of error
- Dependencies
- Status
- Revisit trigger

## 10_ADVERSARIAL_REVIEW.md
Cada crítica debe ser específica y accionable.

## 11_DEFENSE_AND_REVISION.md
Debe responder crítica por crítica y registrar cambios.

## FINAL_TECHNICAL_DISCOVERY.md
Debe ser autocontenido y utilizable como input para la siguiente etapa: elaboración de ADRs asistidos por IA y especializados para el proyecto, seguida de arquitectura detallada. El artefacto no debe intentar definir un protocolo genérico para producir esos ADRs.
