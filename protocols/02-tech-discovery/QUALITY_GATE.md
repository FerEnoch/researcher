# Quality Gate

Antes de cerrar el Technical Discovery verificar:

- [ ] Cada decisión importante tiene trazabilidad al Product Brief.
- [ ] Las decisiones irreversibles fueron revisadas adversarialmente.
- [ ] Las alternativas descartadas están documentadas.
- [ ] Los riesgos de seguridad críticos tienen mitigación.
- [ ] Los datos sensibles están identificados.
- [ ] Los boundaries de tenancy están definidos si aplica.
- [ ] Las integraciones críticas tienen fallback o estrategia de fallo.
- [ ] Existen triggers claros para re-arquitectura.
- [ ] Los unresolved están explícitos.
- [ ] No se generó backlog prematuro.
- [ ] El stack recomendado responde a drivers reales.
- [ ] La solución evita complejidad sin evidencia.
- [ ] La estrategia operativa es viable para el equipo.
- [ ] El documento final puede alimentar una etapa de ADRs asistidos por IA y especializados para este proyecto.
- [ ] Se identificaron explícitamente decisiones candidatas a ADR.
- [ ] El protocolo se detuvo antes de producir ADRs definitivos o imponer un workflow genérico para ellos.
